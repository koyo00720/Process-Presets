# Process Presets

## 概要

**各 `.exe` が使用するコア（スレッド）をプリセット管理する軽量 GUI ソフト**です。  
ゲーム、解析ソフト、レンダラーなど、起動済みの Windows プロセスに対して「どの CPU スレッドを使わせるか」を表のチェックだけで設定し、必要なときに適用できます。

CPU アフィニティは常時監視しません。通常はユーザーが **Apply** を押したときだけ設定を変更し、必要な行だけ一定間隔の定期適用を有効にできます。画面に表示する CPU・メモリ情報だけは、設定した間隔（初期値1秒）で更新します。

## 使い方

1. `ProcessPresets.exe` を起動します。
2. メニューの **Presets > New** を押し、対象の `.exe` 名を入力します。例: `example.exe`
3. 行の **Enabled** をオンにし、使わせたい CPU スレッドの列にチェックを入れます。
4. 同じ `.exe` のプロセスが複数ある場合は、適用対象の **Order** を選びます。
5. 対象のソフトを起動してから、その行の **Apply > Once** を押します。

番号を初めて適用すると、未割り当ての番号と実行中 PID をそれぞれ小さい順に対応させ、適用対象を決定します。この内部の対応は、そのプロセスが終了するか、表の下にある **全ての適用状態をリセット** を押すまで維持されます。**PID** 列には適用予定のPIDではなく、その行が最後に実際の適用に成功し、現在も担当しているPIDだけを表示します。

行を無効にしたり、同じ `.exe` の順番が競合しただけでは担当PIDは移動しません。別の行の適用が成功した時点で、そのPIDの担当が新しい行へ移ります。

入力やチェックの変更、プリセットの追加・削除はすぐに保存されます。次回起動時も同じ内容を利用できます。

## 画面の見方

- **Enabled 列**: オンの行だけ適用できます。グループ化した行では1つのチェックでまとめて切り替わります。
- **.exe 列**: 対象プログラムのファイル名です。パスではなくファイル名を指定します。
- **Apply > Once 列**: その行の設定を1回適用します。
- **Apply > Periodic 列**: オンにすると、設定画面で指定した間隔ごとに自動適用します。**Enabled** がオフの間は適用されません。
- **Reset 列**: PID列に表示されている実際の担当プロセスを優先し、CPU アフィニティを全CPUへ戻します。リセットに成功するとその行のPID表示も消えます。
- **Order 列**: 同じ `.exe` の複数プロセスに割り当てる固定の順番、または全プロセスを対象にする **All** を選びます。
- **Priority 列**: 適用時に設定する Windows のプロセス優先度を選びます。
- **PID 列**: その行が最後に適用成功し、現在実際に担当しているプロセスIDを表示します。
- **開始 列**: PID列に1つのPIDだけが表示されている行で、そのプロセスの開始時間を表示します。PID表示が更新されたときに更新されます。
- **CPU 列**: PID列に1つのPIDだけが表示されている行で、そのプロセスがPC全体のCPU処理能力に対して使用している割合を表示します。
- **メモリ 列**: PID列に1つのPIDだけが表示されている行で、そのプロセスのワーキングセットを表示します。
- **CPU構造列**: チェックしたスレッドだけを使用対象にします。上の見出しは CPU の階層です。

同じグループの行間を除き、別グループとの境界、グループ行と非グループ行の境界、および非グループ行同士の間に区切り線を表示します。

表の下の **全ての適用状態をリセット** は、保存されている順番とPIDの対応、および実際の担当状態をすべてクリアします。実行中プロセスの CPU アフィニティ自体は変更しません。

表の直下には **CPU使用率** 行が固定表示されます。表を上下にスクロールしても同じ位置に残り、CPU構造列ごとの論理CPU使用率を0～100%の縦棒で表示します。数値のパーセント表示は行わず、横方向は表と一緒にスクロールします。

設定画面では、開始・CPU・メモリ列とCPU使用率行を個別に表示／非表示へ切り替えられます。各列の幅、表の文字サイズと行の高さ、CPU使用率行専用の高さ、棒の幅・色・透明度、CPU・メモリ情報の更新間隔、区切り線の太さと透明度、定期適用の間隔も変更できます。**適用** ボタンを押すと、設定ダイアログを閉じずに変更を保存して画面へ反映できます。

## メニュー

- **Presets**: プロセスごとの設定を追加・削除します。
- **CPU Structure**: 表の CPU 見出しを、実機に合わせて編集します。ラベル、階層数、順序を自由に設定できます。`Ctrl` と `Shift` による複数行選択も可能です。
- **Settings**: テーマ、表示言語、各情報列とCPU使用率行の表示、列幅、表の文字サイズと行の高さ、CPU使用率行の高さと棒の幅・色・透明度、情報の更新間隔、区切り線の太さと透明度を設定します。

初回起動時は Windows が検出した CPU 構造をもとに、見出しを自動作成します。すべてのコアが1スレッドなら `P1`、`E1` のような1階層表示になります。SMT を含む場合は `Core → Thread`、複数 CCX を検出した場合は `CCX → Core → Thread`（または `CCX → Core`）の形になります。

## 保存場所

設定、CPU構造、表の内容、順番とPIDの対応、実際の担当状態、各ウインドウのサイズは `ProcessPresets.conf` に保存されます。通常は実行ファイルと同じフォルダです。そのフォルダに書き込めない場合は、Windows のアプリ設定フォルダへ保存します。

CPU構造として「現在のPC（自動検出）」を選んでいる場合、この設定ファイルを別のPCで開くと、そのPCの CPU 構成に合わせて見出しを自動で再検出します。手動で作成した CPU 構造は変更されません。

## 注意点

- このソフトは Windows 専用です。
- 適用対象の `.exe` は、先に起動しておく必要があります。
- CPUスレッドを1つも選択していないプリセットは適用できません。
- 管理者として起動しているプロセスを変更するには、このソフトも同等以上の権限で起動してください。
- Windows の制約により、複数の Processor Group をまたぐ CPU 選択は適用できません。

## 開発者向け: ビルド

Qt 6 と MinGW が必要です。この PC の Qt MinGW キットでは、次の例で Debug / Release をビルドできます。

```powershell
$env:Path = "C:\Qt\Tools\mingw1310_64\bin;C:\Qt\Tools\mingw1310_64\x86_64-w64-mingw32\bin;C:\Qt\6.10.2\mingw_64\bin;$env:Path"
cmake -S . -B build/debug -G Ninja `
  -DCMAKE_BUILD_TYPE=Debug `
  -DCMAKE_MAKE_PROGRAM=C:/Qt/Tools/Ninja/ninja.exe `
  -DCMAKE_PREFIX_PATH=C:/Qt/6.10.2/mingw_64 `
  -DCMAKE_CXX_COMPILER=C:/Qt/Tools/mingw1310_64/bin/g++.exe
cmake --build build/debug

cmake -S . -B build/release -G Ninja `
  -DCMAKE_BUILD_TYPE=Release `
  -DCMAKE_MAKE_PROGRAM=C:/Qt/Tools/Ninja/ninja.exe `
  -DCMAKE_PREFIX_PATH=C:/Qt/6.10.2/mingw_64 `
  -DCMAKE_CXX_COMPILER=C:/Qt/Tools/mingw1310_64/bin/g++.exe
cmake --build build/release

& C:/Qt/6.10.2/mingw_64/bin/windeployqt.exe --release --compiler-runtime `
  --no-translations --force build/release/ProcessPresets.exe
```
